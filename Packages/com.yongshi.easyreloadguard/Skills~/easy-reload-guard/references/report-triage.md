# 处理检查报告

静态报告：`Library/EasyReloadGuard/AuditReport.md`；停止后报告：`ResidueReport.md`；最近一次进入重置失败：`ResetFailureReport.md`。设置页显示静态报告的同一结论。

## 1. 结论和处理责任

0.5.0 按规范判定。每个字段必须由包执行重置，或能由检查器证明初始化后不变；“业务会再次赋值”“纯缓存留着也没事”不再是放行依据。报告只有不符合项和不计入结论的建议。

- 业务已有的订阅、释放、取消缺陷仍由业务修复，不靠清空引用掩盖。修改范围以当前任务授权为准。
- 基类、模板和生成器拥有的状态从源头处理，不逐个改生成物。
- 源码可改时用特性或只在 Editor 编译的重置方法；第三方代码用适配器声明处理。
- 包侧修改与工程接入是不同范围，不能因接入任务擅自修改或发布依赖。

## 2. 不符合项

| 问题 | 处理 | 可暂缓 |
| --- | --- | --- |
| 静态字段、事件、Unity 对象没有处理方式 | 默认初值用 ResetStatic；非默认值/string 用 InitialValue；引用初值用 ResetMethod 恢复 | 是 |
| 只读集合、数组或对象的内容没有处理方式 | 空集合用 Clear；有初始内容或不能确认为空时用重置方法恢复；不变证明见 patterns | 是 |
| 第三方代码的 KnownIssue | 按说明处理或明确暂缓；它不是已处理声明 | 是 |
| async void / 未取消释放的静态异步资源 | 不用 async void；资源放实例；静态入口服务需同类型退出方法对对应字段调用 Cancel / Dispose | 否 |
| 特性用错、ReloadSafe 没原因、ReloadSafe 证明不了 | 修正声明；可变缓存改为重置，不能凭文字原因保留 | 否 |
| 重置方式与字段初值不匹配 | 非默认值不用 Default；已有内容的集合不用 Clear | 否 |
| 重置方法漏掉字段 | ResetMethod / InvokeOnReset 需覆盖类型内所有不能证明不变的字段 | 否 |
| InitializeOnEnterPlayMode 未交给包执行 | 同时加 ResetMethod 或使用 InvokeOnReset，保证重复调用合法 | 否 |
| 适配器找不到目标或用法错误 | 更新类型/成员；SelfHandled 只用于官方来源；HandlesType 已删除 | 否 |
| 内置适配器目标版本未复核 | 由包维护者复核版本后更新；该目标继续逐字段检查 | 否 |
| 泛型未展开 / 无法分析 | 提供闭合类型实参，或解决分析失败；未知不能当作符合 | 否 |

## 3. 建议与未检查范围

私有字段可改为 readonly、成功的泛型展开、初值可能不干净、清单过期行都属于建议。初值可能不干净说明不能安全提前读取该类型，首次重置时采集的值需实测确认。

SelfHandled 官方包、设置排除和目录排除标记均在“未检查范围”中可见。项目 SelfHandled 的字段签名变化提示需重新复核；签名记录可以写入清单，但不计为暂缓的不符合项。内置适配器按版本复核。

## 4. 暂缓清单

文件仍为 `ProjectSettings/EasyReloadGuardBaseline.txt`。升级 0.5.0 先清空旧清单，按新规则重新处理。之后只用“把当前问题列为暂缓”生成允许的条目，修复后可删对应行。

暂缓项不阻止进入 Play，但结论永远包含这些不符合项；不能按“接入完成”交付。编号仅用于文件比对，完整对照见包 README 附录。旧 ReloadSafe 写入位置复核行失效，不能迁为暂缓。

## 5. 停止后检查和验收

- 已销毁的引用：检查字段、回调和集合的持有方是否已释放或解绑。
- 每次增加：核对重复订阅或只加不删；比较从同一脚本域第二次停止开始。
- 有副作用静态构造默认不读取；报告中跳过的部分不代表没有问题。
- 0.5.0 尚无运行时一致性比对、全局写入索引或 ScriptableObject 摘要检查。ResetType 动作的结果须实际验收。

静态检查、Unity 编译、EditMode 测试、连续 Play → Stop 至少三轮分别报告；必须按当前授权执行，没运行的写“未验证”。进入重置失败的 Play 作废；退出并非即时生效，外部文件/网络/原生资源副作用不在自动重载保证范围。
