# 处理检查报告

报告位置：`Library/EasyReloadGuard/AuditReport.md`（静态检查）、`Library/EasyReloadGuard/ResidueReport.md`（停止 Play 后检查）。设置页 `Project Settings/Easy Reload Guard` 显示同样的结果。

## 1. 先判断该谁改（命中第一条就停）

| # | 问题 | 是 → 做法 |
| --- | --- | --- |
| 1 | 开启 Domain Reload、打包后登出重进、切场景、重复 Init 时也会出现？ | 业务本身的缺陷：订阅成对取消、Init 去重、补齐退出释放，不加本包特性。改业务逻辑前先与用户确认方案 |
| 2 | 同一写法出现在很多地方（单例基类、事件中心、生成代码）？ | 改源头：基类、生成模板或生成器，不逐个改生成物 |
| 3 | 只是因为脚本不重新加载，静态变量没回到初值？ | 加本包特性；特性表达不了时写只在 Editor 编译的重置方法 |
| 4 | 第三方或外部官方包，不能改？ | 写 Editor 适配器；公司内部维护的包改包源码（先与用户确认，由用户嵌入或发版） |

判断标准是“上一次 Play 留下的值会不会改变下一次 Play 的结果”，而不是“有没有静态字段”。“主流程没碰到”不算依据，要看源码判断。

## 2. 各类问题的处理

| 问题类型 | 处理 |
| --- | --- |
| 静态事件或委托未处理 | 先确认所有订阅方在销毁或退出时成对取消（缺少就是业务缺陷）；之后在事件上加 `[field: ResetStatic]` |
| 静态 Unity 对象未处理 | 单例常见：下一次 Play 会重新赋值 → `[ResetStatic]`；不会重建 → 重置方法中重建，或确认是持久资产后 `[ReloadSafe]` |
| 静态字段的值会带到下一次 Play | 按读写位置选择，见 [patterns.md](patterns.md) 第 1 节。提示级（私有且只在静态初始化时赋值）可以不处理 |
| 只读集合、数组或对象的内容会带到下一次 Play | 只在静态初始化时填充 → 不要 Clear；运行中增删 → `Clear`；两者都有 → 重置方法 |
| async void 方法 / 静态字段持有异步任务、线程或计时器 | 由发起者传递取消令牌并在停止方法中结束；只置 null 无效 |
| 特性用法错误、`[ReloadSafe]` 没写原因 | 必须修，不能记为已知遗留 |
| 已加的重置会破坏下一次 Play | 改写：只在静态初始化中创建的引用不要置 null，静态初始化中填好的集合不要 Clear |
| 重置方法漏掉了字段 | 在重置方法中处理它，或加 `[ReloadSafe("原因")]` |
| 声明保留的字段仍在 Play 中被修改 | 实际含义是“在静态初始化以外仍被修改”。逐条确认原因仍成立 → 可记为已知遗留；不成立 → 去掉 `[ReloadSafe]`，改用重置 |
| 适配器找不到目标 | 必须修：目标类型或成员改名、删除了 |
| 适配器目标的版本未复核 | 只出现在本包内置的适配器上：升级本包，或请本包维护者复核该版本 |
| 跳过检查的代码中静态字段有变化 | 项目适配器跳过的类型静态字段变了（第一次检查也会出现）。只复核列出的新增、删除字段：不影响下一次 Play → 重新记为已知遗留；会影响 → 改用 `ResetField`、`InvokeOnReset` 或 `KnownIssue` |
| 第三方代码的已知问题 | 适配器如实报告的问题，不算已处理 |

## 3. 停止 Play 后检查

- **仍引用已销毁的对象**：负责的代码没有清理引用或取消订阅。
- **比上次停止时增加**：同一回调或集合每次 Play 都在增加，通常是重复订阅或只加不删。报告给出方法全名，可以直接定位。从本次脚本加载后的第 2 次停止开始比较；只出现一次的初始化（0 → 1 后不再变化）不算增长。
- 读取静态字段会触发静态构造，所以有副作用的静态构造所在类型默认跳过。“没有发现残留”不等于没有残留，跳过和无法读取的数量见报告开头。

## 4. 已知遗留问题清单

`ProjectSettings/EasyReloadGuardBaseline.txt` 记录“已经知道、暂时不修”的问题。清单中的问题不阻止进入 Play，但仍列在报告中。

- 不要手工添加行。确认问题之后，用设置页的“把当前问题记为已知遗留”重新生成；生成会覆盖整个文件。
- 修好一个问题后删除对应行；已没有对应问题的行，报告会提示“遗留问题清单中的过期行”。

## 5. 交付时的证据

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 编译通过，检查报告没有新问题 | 特性被识别，写法没有明显错误 | 运行时行为正确 |
| EditMode 测试通过 | 单元行为 | 工程连续 Play 的结果 |
| 连续 Play → Stop，停止后检查没有新增问题 | 实际走过的流程中没有残留 | 没走到的入口 |

静态检查、编译、测试、实际运行分别报告；没有运行的写“未验证”。
