# Easy Reload Guard 接入手册

README 说明的是每个特性**能做什么**，本手册说明拿到一条检查报告之后**该怎么判断、怎么改、改完怎么证明**。适用于在已有工程（尤其是大量历史代码）中关闭 Domain Reload。

阅读顺序：先读第 1 节的归属判断，再按第 2 节的决策表处理单条报告；动手前对照第 3 节的禁忌清单。大工程的推进节奏见第 5 节。

---

## 1. 先判归属：这个问题该谁改

按顺序回答下面四个问题，**命中第一条就停**。

| # | 问题 | 是 → 归属与做法 |
| --- | --- | --- |
| 1 | 开启 Domain Reload，在 Player 中**登出重进、切场景、重复调用 Init** 时，这个问题也会出现吗？ | **业务缺陷**。修业务本身（成对订阅/解除、Init 去重、退出链补齐释放），不加本包特性。这类修改不算“为本包改业务”。 |
| 2 | 同一种写法在工程中出现了很多处（单例基类、事件中心、生成代码）？ | **改模式的源头**：基类、生成模板、生成器。一处修改覆盖全部派生/生成物，不要逐个改生成物。 |
| 3 | 问题只因为“域不重载 → 静态初值不会回来”？ | **本包声明**：按第 2 节选特性；特性表达不了时写 Editor-only 重置方法（第 4 节）。 |
| 4 | 代码属于第三方或外部官方包，无法修改？ | **Editor 适配器**：调用其自带的清理入口；没有入口时 `KnownIssue` 如实报告，或 `RequireDomainReload` 兜底。公司内部托管的包回到包源码修复。 |

判断问题 1 时，看的是“旧值会不会改变下一次运行的结果”，而不是“有没有静态字段”。

## 2. 按报告处理单条问题

每条报告下面有一行**上下文**，来自只读 IL 分析，统计的是字段在**声明类型内**（含嵌套类型、lambda、async 状态机）的访问情况：

| 上下文项 | 含义 |
| --- | --- |
| 初值 | 是否在类型初始化（字段初值或静态构造）中赋值 |
| 初始内容 | 集合或数组是否在类型初始化中填充（集合初始化器、静态构造中的 Add） |
| 赋值 | 类型初始化以外给字段赋值的方法 |
| 内容修改 | 类型初始化以外修改集合元素、数组元素或调用对象方法的位置（启发式判断） |
| 范围 | 私有字段只能在类型内访问，结论完整；非私有字段的类型外写入**没有分析**，需要自己搜索调用方 |
| 生成代码 | 类型标了 `[GeneratedCode]`：改生成模板 |

报告中的建议已经按上下文给出。下表是同一套判断的完整版，用于复核建议，或在上下文缺失（IL 分析失败）时手工判断。

### 2.1 可变静态字段（RG003）、静态 Unity 对象（RG002）

| 上下文 | 处理 |
| --- | --- |
| 私有，只在类型初始化时赋值或从未赋值，且没有内容修改 | 值不会变：改为 `const` 或 `static readonly`（提示级） |
| 值类型/string，有初值，在 X 中修改 | 初值不是 default → `[ResetStatic(ResetMode.InitialValue)]`；是 default → `[ResetStatic]` |
| 值类型/string，没有初值，在 X 中赋值 | `[ResetStatic]` |
| 引用，没有初值，在 X 中赋值 | 确认下一会话会再经过 X（Awake、Init、判空创建）→ `[ResetStatic]` |
| 引用，有初值，在 X 中重新赋值 | 只有下一会话**必然先**经过 X 时才能用 `[ResetStatic]`；否则写重置方法恢复初值 |
| 引用，只有初值、没有其他赋值 | **不能置 null**（没有重建路径）。对象跨会话有效（持久资产、无状态服务）→ `[ReloadSafe("原因")]`；有会话状态 → 重置方法里重新创建 |
| 非私有，类型内没有赋值 | 搜索类型外的赋值方，按上面几行判断 |

### 2.2 readonly 集合、数组、对象（RG004）

| 上下文 | 处理 |
| --- | --- |
| 只在类型初始化时填充，之后不修改 | **不要 Clear**（静态构造不会再执行，清空后永久为空）。内容确定不变 → `[ReloadSafe("原因")]` |
| 没有初始内容，在 X 中追加/删除 | `[ResetStatic(ResetMode.Clear)]` |
| 既有初始内容，又在 X 中修改 | Clear 会丢失初始内容：写重置方法，清除会话数据并恢复初始内容 |
| 数组元素在 X 中被改写 | 重置方法恢复元素 |
| 对象（缓存、对象池、注册表）在 X 中被调用 | 看对象自身有没有重置入口：有 → 重置方法里调用它；纯计算缓存 → `[ReloadSafe]` |

### 2.3 静态事件与委托（RG001）

1. 找到所有订阅方（`+=` 的位置）。订阅方是会被销毁的对象（MonoBehaviour、System、View）→ 它应在自己的销毁/退出入口里成对 `-=`。缺失时按第 1 节问题 1 处理：**这是业务缺陷**。
2. 订阅方配对完整之后，事件字段本身再加 `[field: ResetStatic]`，作为兜底清掉异常退出时的残留。
3. 不能清的情况：订阅只在静态构造或 `[InitializeOnLoad]` 中登记一次（清掉后不会重新登记）。

### 2.4 异步（RG005、RG006）

由业务 owner 负责，见 README“异步与后台工作”。只置 null 不会停止已在运行的工作。

### 2.5 声明复核（RG013）与 owner 覆盖（RG014）

- **RG013**：已经写下的 `[ResetStatic]` 会破坏下一会话，例如把只在类型初始化中创建的引用置 null，或 Clear 类型初始化中填充的集合。按 2.1/2.2 的表改写声明。确认类型外会重新赋值时，可以写入基线。
- **RG014**：类型有 `[ResetMethod]`，但重置方法（含它调用的类型内方法）没有处理某个可变字段。要么在重置方法里恢复它，要么加 `[ReloadSafe("原因")]` 说明有意保留。不要靠一个局部的 Clear 方法，让整个类型被视为“已处理”。

## 3. 禁忌清单

| 不要这样做 | 原因 | 改为 |
| --- | --- | --- |
| 对只在静态构造中填充的目录/查找表用 `Clear` | 静态构造不会再执行，清空后永久为空（RG013） | `[ReloadSafe]` |
| 对有初值、没有重建路径的引用用 `[ResetStatic]` | 下一会话拿到 null（RG013） | 重置方法重新创建，或 `[ReloadSafe]` |
| 只置空 owner 的引用，不处理它登记到别处的监听/回调 | 旧监听仍在全局表中，随新实例重复累积 | 监听表与 owner 引用在同一批重置；更好的做法是 owner 在销毁时注销 |
| 把字段置 null 当作停止线程、计时器、下载或 Socket | 已在运行的工作不会因此停止 | 调用业务的停止/取消入口 |
| 用类型级、程序集级 `[ReloadSafe]` 或整批基线掩盖未复核的报告 | 新增问题也会被一并忽略 | 逐字段说明；基线只写确认过的遗留问题 |
| 为本包在业务中加登记调用、控制分支、参数或 Unity 消息 | 改变业务流程与 Player 行为 | 特性、Editor-only 重置方法或适配器 |
| 新增 `[OnExitPlayMode]` 方法来释放订阅、线程或资源 | 这些释放在 Player 中同样需要，缺失是业务缺陷 | 修业务的销毁/退出链，再标注已有的停止方法 |
| 手改生成物 | 下次生成会被覆盖 | 改模板或生成器 |
| 只因上下文写“赋值：类型初始化外无”就把非私有字段改为 readonly | 类型外可能有写入（包括反射写入） | 先搜索调用方 |

## 4. Editor-only 重置方法

业务类型没有现成的重置入口、特性又表达不了时（需要恢复初始内容、几个字段之间有不变量、需要重新填充只读表），可以在该类型中新增只在 Editor 编译的重置方法：

```csharp
public static class ConditionRegistry
{
    static readonly Dictionary<int, List<Action>> s_Listeners = new Dictionary<int, List<Action>>();
    static readonly Dictionary<int, string> s_Names = BuildNames();   // 只在类型初始化中填充
    static int s_Version = 1;

    public static void Listen(int id, Action listener) { /* 业务代码不变 */ }

#if UNITY_EDITOR
    [EasyReloadGuard.ResetMethod]
    static void ResetForPlay()
    {
        s_Listeners.Clear();   // 会话数据
        s_Version = 1;         // 恢复初值
        // s_Names 内容不变，不处理；检查器会对它报 RG014，加 [ReloadSafe("只读名称表")] 说明
    }
#endif
}
```

规则：

1. 方法连同特性整体放在 `#if UNITY_EDITOR` 内，Player 中不存在该方法。`static`、无参、`void`、同步、幂等。
2. 只把**本类型**的静态状态恢复为“新域首次进入 Play 时”的样子：初值、空集合、重新填充只读表。不调用业务流程（不 Init、不创建 GameObject、不订阅事件、不派发事件）。
3. 业务代码不调用它，它只由本包在进入 Play 时调用。
4. 类型中的每个可变静态字段，要么由它处理，要么标 `[ReloadSafe]`；检查器用 RG014 核对。
5. 退出 Play 时的释放不适用本规则：`[OnExitPlayMode]` 只能标注业务已有的方法（见第 3 节）。

## 5. 大工程的推进节奏

不要逐条处理全部报告。数千条报告里，大部分是常量式字段、只读目录、第三方包和生成代码。

1. **运行检查**，看报告开头的“工作清单”：按 来源 → 程序集 → 类型 分组，Assets 源码在前、问题多的类型在前。一个类型通常对应一个 owner，按行分工。
2. **先降噪**：提示级的“改为 const/static readonly”、只在类型初始化时填充的只读目录，批量处理或保持提示级不动；生成代码改模板。
3. **收敛模式**：把随手写的单例、事件中心、管理器收敛到少数几种基类/写法，在模式层面加一次特性。这是处理随手代码最省力的方式。
4. **按第 1 节归属逐个类型处理**：业务缺陷修业务，域专属问题加声明。
5. **基线剩余问题**：确认过的遗留问题写入基线，打开 Block，阻止新增问题。
6. **尽早做 PSP**：关闭 Domain Reload、开启 Scene Reload，连续 Play → Stop 至少 3 轮。每次回到编辑模式时，残留探测会写 `Library/EasyReloadGuard/ResidueReport.md`：
   - **已销毁对象的引用**：静态字段或回调仍指向上一会话销毁的对象 → 对应 owner 没有清理或解除订阅。
   - **跨会话增长**：同一回调方法在引擎/编辑器事件或项目委托中的数量逐轮增加，或集合元素逐轮增加 → 重复订阅或只增不删。报告给出方法全名，可直接定位 owner（例如第三方包在 `EditorApplication.playModeStateChanged` 上的累积订阅）。
   - 有静态构造的项目类型默认不读取（读取会触发尚未执行的静态构造）。跳过数量见报告；需要时在设置中打开“残留探测读取有静态构造的类型”。
   让运行结果决定下一步优先级，比继续扩大静态清单更省力。

## 6. 交付证据

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 编译通过、检查报告数量下降 | 声明被识别，没有新增 RG010/RG013/RG014 | 运行行为正确 |
| EditMode 测试通过 | 包与案例的单元行为 | 业务工程的连续 Play |
| PSP + 残留探测无新增项 | 实测场景下的跨会话残留 | 未覆盖的入口（登出重进、加载中退出等需单独走） |

静态检查、编译、测试、PSP 分别报告；未运行的项标记为未验证。
